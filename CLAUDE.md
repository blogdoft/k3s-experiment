# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

Infrastructure provisioning for a home k3s cluster. The controller node is **morgul** (`192.168.1.212`). All services use the `*.home.arpa` wildcard TLS cert and are accessed via Traefik ingress.

This repo handles **bootstrap only**: it provisions k3s, installs ArgoCD, and creates Kubernetes secrets. The actual application manifests live in the separate `github.com/blogdoft/k3s-apps` repo and are deployed by ArgoCD via GitOps.

## Environment Setup

All credentials are in `.env` (gitignored). Copy and fill before running anything:

```bash
ANSIBLE_MORGUL=<ssh-user>
ANSIBLE_PASSWORD=<ssh-password>
DATABASE_HOST=192.168.1.212
HOST_NAME=morgul
K3S_TOKEN=<token>
K3S_DB_USER=<user>
K3S_DB_PASSWORD=<password>
```

The `install.sh` and component scripts call `source .env` — always run from the repo root.

## Key Commands

**Full install (runs all steps in order):**
```bash
./install.sh
```

**Full uninstall:**
```bash
./uninstall.sh
```

**Server preparation (run once on new nodes):**
```bash
ansible-playbook playbooks/prepare-server.yaml -i inventory.yaml
```

**Install k3s controller only:**
```bash
ansible-playbook playbooks/install-controller.yaml -i inventory.yaml
```

**Reset and recreate all databases** (drops and recreates `flagr`, `k3s`, `kc-cluster`):
```bash
cd databases && ./configure.sh
```
Requires Docker running locally and the Postgres instance at `$DATABASE_HOST` to be reachable.

**Re-run individual component setup:**
```bash
cd argocd && ./install.sh    # reinstall ArgoCD + register k3s-apps repo + bootstrap root-app
cd keycloak && ./install.sh  # recreate keycloak secrets and realm configmaps
cd flagr && ./install.sh     # recreate flagr secrets
cd flagr && ./postinstall.sh # recreate oauth2-proxy secrets (queries Keycloak DB)
cd openbao && POD_NAME=openbao-0 ./init.sh  # initialize and unseal OpenBao
```

**Apply wildcard TLS cert** (requires `_wildcard.home.arpa+1.pem` and `_wildcard.home.arpa+1-key.pem` generated by mkcert to be placed in `ingress/`):
```bash
cd ingress && ./install.sh
```

## Architecture

### Install Sequence

`install.sh` runs in this order — the sequence matters because later steps depend on earlier ones:

1. `databases/configure.sh` — drops/recreates databases via Docker-based `psql`
2. `ansible-playbook playbooks/install-controller.yaml` — installs k3s on `morgul`, copies kubeconfig locally
3. `flagr/install.sh` — creates `postgres-credentials` secret in `flagr` namespace
4. `kubectl apply -f dns/` — patches CoreDNS to forward `home.arpa` queries to `192.168.1.203`
5. `keycloak/install.sh` — creates DB secret + realm configmap in `keycloak` namespace
6. `argocd/install.sh` — installs ArgoCD, registers the `k3s-apps` repo (prompts for SSH key path), applies root bootstrap app, waits for all apps to sync
7. Manual pause: configure Longhorn disk tags (`ssd`) at `https://longhorn.home.arpa`
8. Manual pause: unseal OpenBao at `https://openbao.home.arpa`
9. `openbao/init.sh` — initializes OpenBao and runs unseal (writes keys to `openbao/openbao-*.txt`, all gitignored)
10. `rancher/install.sh` — waits for Rancher deploy, pins it to `morgul` node
11. `flagr/postinstall.sh` — queries the Keycloak DB for the `flagr` client secret and creates `oauth2-proxy-secrets`

### K3s Datastore

k3s uses **PostgreSQL** (not embedded etcd) as its datastore. The Postgres instance is external to the cluster, running on `morgul` itself (`192.168.1.212:5432`). The datastore connection string is built from `inventory.yaml` vars sourced from `.env`.

### GitOps Split

- **This repo**: k3s installation, secret bootstrapping, ArgoCD installation
- **`github.com/blogdoft/k3s-apps`**: All application Kubernetes manifests (Longhorn, OpenBao, Keycloak, Rancher, Flagr, etc.), managed by ArgoCD. Changes to running workloads go there, not here.

### TLS

Wildcard cert for `*.home.arpa` is generated locally with mkcert and distributed by `ingress/install.sh`:
- Stored as Kubernetes secrets `wildcard-home-arpa`, `traefik-tls-cert`, and `traefik-default-cert` in `kube-system`
- Distributed to all nodes via Ansible (`ingress/ansible/playbook.yaml`) so containerd trusts it
- The CA cert is exported to `./home-arpa-ca.crt` at the end of `install.sh` for browser import

### Sensitive Files (all gitignored)

- `.env` — all credentials
- `openbao/openbao-init.json`, `openbao-root-token.txt`, `openbao-unseal-keys.txt` — vault init output
- `**/*.crt`, `**/*.key`, `**/*.pem` — TLS material
